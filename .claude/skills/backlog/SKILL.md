# 개선요청 관리 스킬 (/backlog)

개선요청 게시판에서 접수된 요청을 BACKLOG.md에 기록하고, 처리 상태에 따라 관련 문서를 업데이트합니다.

## 대상 문서

@docs/05-tracking/BACKLOG.md
@docs/05-tracking/CHANGELOG.md
@docs/01-planning/PRD.md
@docs/05-tracking/PROGRESS.md
@docs/01-planning/Roadmap.md

## 실행 절차

### 1단계: 사용자에게 질문

스킬 실행 시 **반드시 먼저** 사용자에게 다음을 질문합니다:

**질문 내용:**
```
어떤 개선요청을 처리할까요?

1. 📥 신규 접수 - 새로운 개선요청 등록
2. 🔄 상태 변경 - 기존 요청의 상태 변경 (대기→진행중, 진행중→완료 등)
3. 📋 현황 확인 - 현재 백로그 현황 요약
```

### 2단계: 유형별 처리

#### 📥 신규 접수

사용자에게 다음 정보를 확인합니다:
- **제목**: 개선요청 제목
- **유형**: 버그(🐛) / 개선(💡) / 기능추가(✨) / 기타(📝)
- **우선순위**: 긴급(🔴) / 높음(🟠) / 보통(🟡) / 낮음(🟢)
- **요청자**: 누가 요청했는지
- **관련 메뉴**: 어느 화면/기능에 관련된 것인지
- **상세 내용**: 구체적인 내용 (선택)

처리:
1. BACKLOG.md에서 마지막 ID 확인 → 다음 ID 자동 부여 (IMP-001, IMP-002, ...)
2. `📋 대기 (Pending)` 테이블에 행 추가
3. `updated` 타임스탬프 갱신

#### 🔄 상태 변경

사용자에게 다음 정보를 확인합니다:
- **대상 ID**: 어떤 요청인지 (IMP-xxx)
- **변경할 상태**: 대기→진행중, 진행중→완료, 대기→보류, 대기→반려 등
- **메모**: 상태 변경 사유 (선택)

**상태별 처리:**

| 변경 | 처리 내용 |
|------|----------|
| → 진행중 | `대기` 테이블에서 제거 → `진행중` 테이블에 추가 (담당자, 착수일, 예정일 기록) |
| → 완료 | `진행중` 테이블에서 제거 → `완료` 테이블에 추가 (완료일, 변경내용 기록) + **CHANGELOG 업데이트** |
| → 보류 | `대기/진행중` 테이블에서 제거 → `보류` 테이블에 추가 (보류 사유 기록) |
| → 반려 | `대기` 테이블에서 제거 → `반려` 테이블에 추가 (반려 사유 기록) |

#### 📋 현황 확인

BACKLOG.md를 읽어서 현황을 요약합니다:
- 대기 건수, 진행중 건수, 완료 건수, 보류/반려 건수
- 긴급/높음 우선순위 항목 목록
- 최근 완료된 항목

### 3단계: 연동 문서 업데이트 (완료 시)

요청이 **완료** 상태로 변경될 때, 유형에 따라 추가 문서를 업데이트합니다:

| 유형 | 업데이트 대상 |
|------|-------------|
| 🐛 버그 | CHANGELOG.md `[Unreleased]` > 수정 (Fixed) |
| 💡 개선 | CHANGELOG.md `[Unreleased]` > 개선 (Improved) |
| ✨ 기능추가 | CHANGELOG.md `[Unreleased]` > 추가 (Added) + PRD.md + PROGRESS.md + Roadmap.md |
| 📝 기타 | CHANGELOG.md `[Unreleased]` > 해당 카테고리 |

**CHANGELOG 기록 형식:**
```markdown
### 수정 (Fixed)
- [IMP-001] 로그인 시 빈 화면 표시되는 오류 수정
```

## ID 규칙

- 형식: `IMP-XXX` (3자리 숫자, 제로패딩)
- 예: IMP-001, IMP-002, ..., IMP-100
- BACKLOG.md의 모든 테이블(대기/진행중/완료/보류/반려)에서 가장 큰 ID + 1

## 테이블 형식

### 대기 테이블
```markdown
| ID | 유형 | 우선순위 | 제목 | 요청자 | 접수일 | 관련 PRD | 비고 |
```

### 진행중 테이블
```markdown
| ID | 유형 | 우선순위 | 제목 | 담당자 | 착수일 | 관련 PRD | 예정일 |
```

### 완료 테이블
```markdown
| ID | 유형 | 제목 | 완료일 | 반영 버전 | 관련 PRD | 변경 내용 |
```

### 보류/반려 테이블
```markdown
| ID | 유형 | 제목 | 보류일/반려일 | 보류/반려 사유 |
```

## 응답 형식

### 신규 접수 후
```
📥 개선요청 접수 완료

**ID:** IMP-001
**제목:** [제목]
**유형:** 🐛 버그
**우선순위:** 🟠 높음
**요청자:** [요청자]
**접수일:** 2026-02-27

→ BACKLOG.md `대기` 테이블에 추가됨
```

### 상태 변경 후
```
🔄 상태 변경 완료

**ID:** IMP-001
**변경:** 진행중 → 완료
**완료일:** 2026-02-27

**연동 문서 업데이트:**
- CHANGELOG.md: [Unreleased] > 수정 (Fixed)에 추가
- BACKLOG.md: `진행중` → `완료` 테이블 이동

→ 다음 배포 시 버전에 포함됩니다
```

### 현황 확인
```
📋 백로그 현황

| 상태 | 건수 |
|------|------|
| 📋 대기 | N건 |
| 🔨 진행중 | N건 |
| ✅ 완료 | N건 |
| ⏸️ 보류 | N건 |
| 🚫 반려 | N건 |

**주의 필요:**
- 🔴 [IMP-xxx] 긴급 - [제목]
- 🟠 [IMP-xxx] 높음 - [제목]
```

## 주의사항

1. **반드시 질문 먼저**: 스킬 실행 시 바로 문서를 수정하지 않고, 사용자에게 먼저 질문
2. **ID 자동 부여**: 사용자가 ID를 지정하지 않으면 자동으로 다음 번호 부여
3. **symlink 파일**: BACKLOG.md와 CHANGELOG.md는 Obsidian 볼트로의 symlink 파일. 정상 읽기/쓰기 가능
4. **타임스탬프**: 문서 수정 시 frontmatter의 `updated` 필드를 현재 시각으로 갱신
5. **CHANGELOG 연동**: 완료 처리 시 반드시 CHANGELOG.md의 `[Unreleased]` 섹션에도 기록
