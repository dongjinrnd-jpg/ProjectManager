# 개선요청 게시판 (Improvement Board)

> 시스템 운영 중 발생한 문제점 및 개선사항을 등록/관리하는 게시판

---

## 1. 개요

### 1.1 목적
- 시스템 가동 후 발생하는 버그, 불편사항, 개선요청을 체계적으로 수집
- 요청 사항의 진행 상태를 투명하게 공유
- 개발 우선순위 결정을 위한 데이터 축적

### 1.2 대상 사용자
| 권한 | 조회 | 작성 | 수정 | 삭제 | 상태변경 |
|------|------|------|------|------|----------|
| user | X | X | X | X | X |
| engineer | O | O | 본인만 | 본인만 | X |
| admin | O | O | 본인만 | 본인만 | X |
| executive | X | X | X | X | X |
| sysadmin | O | O | 모두 | 모두 | O |

---

## 2. 기능 요구사항

### 2.1 게시판 목록 화면 (/improvements)

#### 헤더 영역
```
📋 개선요청 게시판                              [+ 새 요청] 버튼
```

#### 필터 영역
```
[상태 ▼] [유형 ▼] [우선순위 ▼] [🔍 검색...]
```

- **상태 필터:** 전체 / 접수 / 검토중 / 진행중 / 완료 / 보류 / 반려
- **유형 필터:** 전체 / 버그 / 개선요청 / 기능추가 / 기타
- **우선순위 필터:** 전체 / 긴급 / 높음 / 보통 / 낮음
- **검색:** 제목, 내용 키워드 검색

#### 테이블 컬럼
| No | 상태 | 유형 | 우선순위 | 제목 | 작성자 | 작성일 | 처리예정일 |
|----|------|------|----------|------|--------|--------|------------|

- **No:** 자동 번호 (IMP-001, IMP-002, ...)
- **상태:** 배지 색상으로 구분
  - 🔵 접수 (파랑)
  - 🟡 검토중 (노랑)
  - 🟠 진행중 (주황)
  - 🟢 완료 (초록)
  - ⚪ 보류 (회색)
  - 🔴 반려 (빨강)
- **유형:** 아이콘으로 구분
  - 🐛 버그
  - 💡 개선요청
  - ✨ 기능추가
  - 📝 기타
- **우선순위:** 색상 표시
  - 🔴 긴급
  - 🟠 높음
  - 🟡 보통
  - 🟢 낮음

#### 페이지네이션
```
< 1 2 3 ... > 총 N건
```

### 2.2 요청 등록/수정 화면

#### 필수 입력
- **제목** (텍스트, 최대 100자)
- **유형** (드롭다운: 버그/개선요청/기능추가/기타)
- **내용** (텍스트 에어리어, 마크다운 지원)

#### 선택 입력
- **관련 메뉴** (드롭다운: 대시보드/프로젝트/업무일지/주간보고/일정/검색/설정/기타)
- **우선순위** (드롭다운: 긴급/높음/보통/낮음, 기본값: 보통)
- **재현 방법** (버그인 경우, 텍스트 에어리어)
- **첨부 스크린샷** (이미지 URL 입력 - 추후 파일 업로드로 개선)

#### 자동 입력
- **작성자:** 로그인 사용자
- **작성일:** 현재 날짜
- **상태:** 접수 (기본값)

### 2.4 관리자 기능 (sysadmin 전용)

#### 상태 변경
- 드롭다운으로 상태 변경
- 변경 시 처리 메모 입력 (필수)
- 처리 이력에 자동 기록

#### 우선순위/처리예정일 설정
- 접수된 요청에 우선순위 재설정
- 처리예정일 지정

#### 일괄 처리
- 체크박스로 여러 건 선택
- 일괄 상태 변경

## 3. 데이터 구조

### 3.1 Improvements 시트
```typescript
interface Improvement {
  id: string;              // IMP-001 형식
  title: string;           // 제목
  type: 'bug' | 'improvement' | 'feature' | 'other';  // 유형
  status: 'submitted' | 'reviewing' | 'in_progress' | 'completed' | 'hold' | 'rejected';
  priority: 'urgent' | 'high' | 'normal' | 'low';    // 우선순위
  content: string;         // 내용 (마크다운)
  relatedMenu: string;     // 관련 메뉴
  reproductionSteps: string;  // 재현 방법 (버그인 경우)
  screenshotUrl: string;   // 스크린샷 URL

  authorId: string;        // 작성자 ID
  authorName: string;      // 작성자 이름
  createdAt: string;       // 작성일시
  updatedAt: string;       // 수정일시

  dueDate: string;         // 처리예정일
  completedAt: string;     // 완료일시
}
```

### 3.2 ImprovementHistories 시트
```typescript
interface ImprovementHistory {
  id: string;              // 히스토리 ID
  improvementId: string;   // 개선요청 ID
  status: string;          // 변경된 상태
  memo: string;            // 처리 메모
  changedBy: string;       // 변경자 ID
  changedByName: string;   // 변경자 이름
  changedAt: string;       // 변경일시
}
```

### 3.3 ImprovementComments 시트
```typescript
interface ImprovementComment {
  id: string;              // 댓글 ID
  improvementId: string;   // 개선요청 ID
  content: string;         // 댓글 내용
  authorId: string;        // 작성자 ID
  authorName: string;      // 작성자 이름
  createdAt: string;       // 작성일시
}
```

## 4. API 설계

### 4.1 개선요청 API
| Method | Endpoint | 설명 | 권한 |
|--------|----------|------|------|
| GET | /api/improvements | 목록 조회 | engineer, admin, sysadmin |
| GET | /api/improvements/[id] | 상세 조회 | engineer, admin, sysadmin |
| POST | /api/improvements | 등록 | engineer, admin, sysadmin |
| PUT | /api/improvements/[id] | 수정 | 작성자, sysadmin |
| DELETE | /api/improvements/[id] | 삭제 | 작성자, sysadmin |
| PATCH | /api/improvements/[id]/status | 상태 변경 | sysadmin |

### 4.2 댓글 API
| Method | Endpoint | 설명 | 권한 |
|--------|----------|------|------|
| GET | /api/improvements/[id]/comments | 댓글 목록 | engineer, admin, sysadmin |
| POST | /api/improvements/[id]/comments | 댓글 등록 | engineer, admin, sysadmin |
| DELETE | /api/improvements/[id]/comments/[commentId] | 댓글 삭제 | 작성자, sysadmin |
